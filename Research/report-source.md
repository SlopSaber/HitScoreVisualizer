# HSV note occlusion investigation

Audience: HitScoreVisualizer maintainer. Date: 2026-09-24. Scope: Beat Saber 1.45.1, ordinary colored notes with Beat Saber Plus Note Tweaker, and HSV score text. Runtime visual proof of the revised build remains pending.

## Answer

The previous patch changed opaque note materials from queue 2004 to queue 5000 and put HSV text at queue 4999. The user confirmed that HSV still appeared over regular notes. Moving the note materials between render passes was the wrong control for this case. The replacement keeps their original materials and adds a colorless stencil pass to visible note meshes. HSV text skips pixels marked by that pass.

## Evidence

- `maincore_assets_all_99a08e87d16158a623e17b8fbaf08c8d.bundle` in the selected game instance contains `NoteHD` and `NoteLW` materials at custom render queue 2004. `sharedassets_assets_all_17ff2f2656a30f8c3f2137b43f7de416.bundle` contains their `Custom/NoteHD` and `Custom/NoteLW` shaders. The HD shader is tagged `RenderType=Opaque`, `RenderPipeline=UniversalPipeline`, and has a `UniversalForwardOnly` pass. This is direct inspection of the installed 1.45.1 assets.
- The same asset bundle gives the `NoteCube` mesh one submesh. [Unity's Mesh Renderer manual](https://docs.unity3d.com/ja/2021.2/Manual/class-MeshRenderer.html) says an additional material renders the last submesh again, allowing a second pass without replacing the note's material.
- [Unity's URP Render Objects documentation](https://docs.unity3d.com/kr/Packages/com.unity.render-pipelines.universal%4015.0/manual/renderer-features/renderer-feature-render-objects.html) confirms opaque and transparent objects use separate render passes. The assertion that the queue change caused this particular failure is an inference; no frame capture identified the rejected draw call.
- [Unity's stencil documentation](https://docs.unity3d.com/cn/2018.3/Manual/SL-Stencil.html) defines the read and write masks and `Replace` and `NotEqual` operations used by the new mask. [Unity's TextMesh Pro overlay shader source](https://github.com/Unity-Technologies/FPSSample/blob/master/Assets/TextMesh%20Pro/Resources/Shaders/TMP_SDF%20Overlay.shader) shows the text shader supports stencil comparison.
- `PublicMods/BeatSaberPlus/Modules/BeatSaberPlus_NoteTweaker/Patches/PGameNoteController.cs` scales note transforms; `PColorNoteVisuals.cs` changes material property blocks. They do not replace the note body shader or its render queue in the inspected paths.

## Implementation and limit

At note spawn, HSV appends one shared `UI/Default` material to each opaque note renderer. It writes stencil bit 128, writes no color, and keeps note materials intact. HSV text draws at queue 4999 only where that bit is absent. The mask material is removed at scene disposal. A one-time gameplay log reports the number of note renderers receiving the mask.

On 2026-09-25, the user reported that floor walls still covered HSV text after the stencil build loaded. The 01:36 game log shows two opaque renderers masked on the first `GameNoteController`, so the note mask initialized. Direct inspection of `textmeshprofonts_assets_all_443dd57f3b25de7f4f987bff059a86a6.bundle` found the active `Teko-Medium SDF Material` uses shader `TextMeshPro/Mobile/Distance Field Zero Alpha Write`. The old HSV shader switch recognized only the standard Distance Field names and therefore left that shader in place. Its installed pass uses `ZTest unity_GUIZTestMode`, so walls may still win depth tests. `core_assets_all_5637ce1f65836a5769cf663a65cc9fbe.bundle` contains `TextMeshPro/Distance Field Overlay`, whose installed pass has `ZTest Always` and stencil comparison properties. HSV now chooses that shader for gameplay text regardless of the font's original shader. The 1.45.1 build succeeded with zero errors and is staged while Beat Saber runs; floor visibility and note masking require a fresh runtime check.

The user then restarted and supplied a screenshot: score text over bright floor geometry was washed out, and they reported that the new shader enabled bloom. The 01:50 log confirms `TextMeshPro/Mobile/Distance Field Zero Alpha Write -> TextMeshPro/Distance Field Overlay`. Installed shader inspection found the original shader blends color with factors `(One, OneMinusSrcAlpha)` and alpha with `(Zero, OneMinusSrcAlpha)`. The stock overlay shader uses `(One, OneMinusSrcAlpha)` for both color and alpha. The changed alpha blend is a plausible cause of the new bloom; the screenshot does not isolate every post-processing contribution.

The replacement shader is based on the local Text Mesh Pro mobile overlay shader source in `PublicMods/SiraLocalizer/Unity/SiraLocalizer/Assets/TextMesh Pro/Shaders`. Its compiled pass has `ZTest Always`, the original alpha blend, and the stencil properties used by the note mask. It was built as a Windows asset bundle with Unity 6000.3.19f1, matching the installed game, and embedded in the HSV DLL. [Unity documents loading an AssetBundle from memory](https://docs.unity3d.com/cn/6000.0/ScriptReference/AssetBundle.html), and the bundle's compiled shader state was inspected directly. Runtime visibility and color still require a restart and manual check.

The user replayed the installed DLL on `Somewhere Out There` (`ExpertStandard.dat`) and reported that its water floor could still hide HSV. The 03:06 game log shows `The AssetBundle 'Memory' could not be loaded because it is not compatible with this newer version of the Unity runtime`, followed by HSV's shader-load error. The bundled shader was never used in that session. The map has 3,746 noninteractive obstacle objects, including 808 on the `lyrics` track from beats 826.25 to 849.50; that confirms substantial wall-based geometry late in the map but does not prove which wall covers a given score label.

The build project had an empty Unity package manifest, so its Asset Bundle module was disabled. Unity's build log explicitly said `'AssetBundle' is not supported because the module AssetBundle is disabled in the build.` The bundle's serialized file contained a Shader but no AssetBundle directory object. This explains why a successful build command had produced an unloadable bundle. The project now enables `com.unity.modules.assetbundle`, and the rebuilt bundle has Shader, Material, and AssetBundle objects plus addresses for both assets. Its compiled shader still has `ZTest Always`, the original zero-alpha blend, and stencil controls. The build command also opens its own output and loads the shader before succeeding. The DLL build has zero errors. The game restarted during the work and installed the corrected DLL, but it has not reached gameplay; shader load and the visual result remain unconfirmed.
